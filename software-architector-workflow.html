8 Specialized Subagents (agents/bv-*.md)

🛠️ bv-executor Sonnet / Session

Implements exactly one ticket by the Test-First principle (first a failing test → REDPROOF, then the code). Writes strictly inside the file zone of its ticket.

Tools: Read, Write, Edit, Bash, Grep, Glob · Returns a contract of ≤ 25 lines

🧐 bv-reviewer Opus (Read-Only)

Checks the code along 3 axes (Manifest, Spec, Craft) and a security checklist. Works in the modes spot (one ticket), repair and branch (the whole branch).

Tools: Read, Grep, Glob, Bash (read only and one-line probes)

🕵️ bv-blind Opus (Gate G4)

Independent acceptor. Works in a clean clone without git history and without access to spec.md or manifest.md. Compares the live run with the words of the brief.

Returns a JSON verdict (run, outcome.solved, requirements, unlisted)

🔍 bv-coverage Sonnet (Gate G2)

Compares the verbatim user briefs with spec.md. Looks for missed (missing), half-covered (half) and extra (extra) features.

Tools: Read, Grep, Glob · A hook blocks access to the other files of the run

🌐 bv-research Sonnet (Web)

Checks on the internet the current library versions, exact signatures of external APIs, limits and licenses before the spec is written.

Tools: WebSearch, WebFetch, Read, Write (writes only research.md)

🤖 bv-scout Haiku

Studies the existing code of the repository before the spec is written: modules, conventions, run commands, exact entity names and traps.

Tools: Read, Grep, Glob, Bash (read-only), Write (only notes.md)

🧠 bv-memory Haiku

Updates the block in AGENTS.md (or prepares memory-proposal.md) only with commands verified in blind acceptance and the current structure.

Called in Phase 7 after G4 passes

📐 bv-adr Haiku (Tier T2+)

Records architecture decisions that are costly to reverse in docs/adr/NNNN-*.md and keeps the glossary of project terms in CONTEXT.md.

Reads only spec.md, manifest.md, interfaces.md and notes.md
5 Programmatic Gates (checked by the bv tool against facts, not on trust)

Gate G1 — Manifest completeness Transition 2 → 3

Checked when bv stage spec start is called. The manifest must hold at least one end-to-end scenario S## and no row with status open without an explanation.

Gate G2 — Spec coverage Phase 3

bv gate G2 itself takes the list of remarks from the final answer of the bv-coverage agent in the hook journal. The orchestrator must close each remark by an exact quote.

Gate G3 — Plan correctness Phase 4

bv tickets checks that ticket numbers are unique, no requirement is lost, the dependency waves are in the right order and file zones in one wave do not overlap.

Gate G5 — Clean clone Phase 7 (Step 1)

bv verify clones the current HEAD into a temporary folder without .software-architector, runs setupCmd, checkCmd and e2eCmd and checks the exit codes and the test count.

Gate G4 — Blind acceptance Phase 7 (Step 2)

bv gate G4 reads the JSON verdict of the bv-blind agent directly from the SubagentStop hook journal. Requires a green G5 on the same commit and the answer outcome.solved: true.

8 Lifecycle Hooks (hooks/hooks.json → scripts/guard.py & scripts/events.py)

1. PreToolUse (Main barrier) bv hook pre-tool

Intercepts Write, Edit, Read, Grep, Glob, Bash, PowerShell, WebSearch, WebFetch, Agent and MCP. If the check fails or exceeds the timeout, a call that writes is blocked (fail-closed).

2. Role and zone isolation Write protection

The orchestrator cannot change project code. The executor (bv-executor) can write only to the Zone of its ticket. No agent can edit state.json or the live/ journal.

3. Secret and Git protection Data protection

Reading .env is blocked. API keys/tokens are cut out before writing to disk. git push, reset --hard, clean -f, stash and a direct git commit are blocked.

4. Agent event journal events.py

The hooks PostToolUse, PostToolUseFailure, SubagentStart and SubagentStop write each step of an agent to .software-architector/live/<run>/ and keep the answers of the checkers for bv.

5. VS Code panel hooks/register.tsx

Opens to the right of the chat automatically. Shows the mode, gates G1–G5, the tree «stage → tickets → agents», the current command of each agent, and the counters of errors ✗N and blocks ⛔N.

6. Local Web Dashboard scripts/dashboard.html

Starts on 127.0.0.1:87NN/?k=<key> through bv serve / bv web. Refreshes every 2 seconds and lets you view the full input and output of every tool call.
