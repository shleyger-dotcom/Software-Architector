Software-Architector v4.0.2 — Plugin Workflow and Architecture

Interactive map: 8 run phases (0–7) · 5 hard gates (G1–G5) · Dual-gate code stages · Stage & final receipts · 8 subagents · 8 lifecycle hooks
Entry point (Claude Code): /software-architector:build [full|semi|interview] [strict|normal|deep] <idea or brief.md> No arguments → resumes active run · Finished product extension → bv reopen
Dual-Gate Code Stages (v4.0.0) Every code stage (ticket commit, branch review, delivery) requires both an execution check (checkCmd / bv verify) and a code audit (audit.scan / bv audit + bv-reviewer) on the current HEAD.
Full Re-Check After Any Patch Repairs patch only the named defect (max 2 F rounds per stage). Any new commit marks G5, G4, audit and review stale and re-runs every check of that stage from the start.
Stage & Delivery Receipts Closing any stage writes a factual Receipt — stage … into receipts.md. bv finish prints the final verbatim Receipt (files, tickets, gates, audit) into the user report.

8 Specialized Subagents (agents/bv-*.md — only software-architector:bv-* allowed during a run)

🛠️ bv-executor Sonnet / Session

Implements exactly one ticket Test-First (failing test → REDPROOF → code). Writes strictly inside its ticket's Zone (plus .env.example and allowed manifests) and removes its own debug/dead leftovers.

Tools: Read, Write, Edit, Bash, Grep, Glob · Contract ≤ 25 lines (8 required keys)

🧐 bv-reviewer Opus (Read-Only)

Judges code along Manifest (spot only), Spec and Craft axes plus a mandatory security checklist. Runs in spot, repair and branch modes; confirms or refutes every blocker/high item in audit.md. Its DROP: … [<id>] line (branch and spot modes) is the only thing bv audit --accept accepts.

Tools: Read, Grep, Glob, Bash (guard enforces read-only & inline -e/-c probes)

🕵️ bv-blind Opus (Gate G4)

Independent acceptor. Works exclusively inside the bv blind-clone folder (extracted via git archive without git history or .software-architector/), installs & starts the product, walks S## scenarios live and checks every brief line.

Tools: Read, Grep, Glob, Bash (writes confined to clone) · Pure JSON verdict

🔍 bv-coverage Sonnet (Gate G2)

Independent reader comparing all dated briefs (with ## Additions) against spec.md. Reports missing, half and extra scope items without seeing manifest.md or tickets.

Tools: Read, Grep, Glob · Hook blocks rest of .software-architector/

🌐 bv-research Sonnet (Web)

Replaces model memory with dated official sources before the spec: current stable versions, exact API calls, rate limits, pricing tiers and SPDX licenses. Treats web pages strictly as untrusted data (flags prompt injection under ## Suspicious).

Tools: WebSearch, WebFetch, Read, Write (hook allows writing only research.md)

🤖 bv-scout Haiku

Maps existing repository code before the spec is written: module layout, conventions, verified vs guessed commands, exact entity/route names, post-landing commits and traps.

Tools: Read, Grep, Glob, Bash (read-only), Write (only notes.md)

🧠 bv-memory Haiku

Describes the delivered code as it actually runs (never reads spec.md or tickets): updates AGENTS.md between markers (+ docs/architecture.md on T2+), or writes memory-proposal.md when the memory file belongs to the user.

Tools: Read, Write, Edit, Bash, Grep, Glob · Runs in Phase 7 after G4

📐 bv-adr Haiku (Tier T2+)

Documents costly-to-reverse decisions and D## build constraints in docs/adr/NNNN-<slug>.md, and maintains project terminology in CONTEXT.md or GLOSSARY.md without reading source code.

Tools: Read, Write, Grep, Glob · Reads spec, manifest, interfaces & notes
5 Programmatic Gates + Dual-Gate Verification Model (enforced by scripts/bv.py)

Gate G1 — Manifest completeness Transition 2 → 3

Checked automatically by bv stage spec start: manifest is non-empty, contains at least one live end-to-end scenario S##, and has zero unexplained open rows (zero open rows at all in full mode). Locks requirementIds.

Document gate · Prevents silent requirement drops

Gate G2 — Spec coverage Phase 3

bv gate G2 reads bv-coverage's JSON items directly from the hook journal (SubagentStop / SubagentHandback). Every item must be closed by exact quote with fixed, deferred, cut, or attached to an existing A## row.

Independent journal proof · Blocks bv stage build start

Gate G3 — Plan & Zone integrity Phase 4

bv tickets checks unique ticket IDs, zero vanished or open rows, every live requirement assigned, valid relative Zone paths, dependency waves strictly earlier, zero zone overlap within a wave, and ≤ 2 F tickets per stage.

Plan gate · Transitions in-spec → in-ticket

Gate G5 — Clean clone execution Phase 6 & Phase 7

bv verify clones HEAD into a temp folder without .software-architector/, populates .env from .env.example + CI=1, runs setupCmd, checkCmd and e2eCmd, and requires exit 0 plus a counted test run. Required to close Phase 6 and verified fresh on HEAD in Phase 7.

Execution gate · Tied to exact HEAD commit hash

Gate G4 — Blind acceptance Phase 7

bv gate G4 (accepts no stdin or --from!) reads bv-blind's JSON verdict straight from the hook journal after a green G5 on the same HEAD. Requires run.ok: true, outcome.solved: true, every delivered row verified, and no unmapped brief gaps.

Acceptance gate · Tied to exact HEAD commit hash

Dual-Gate & Receipts Invariant v4.0.0 Core

Every code stage requires Execution + Audit on HEAD: bv commit runs checkCmd + per-ticket audit.scan; Phase 6 requires bv audit + bv-reviewer + bv verify; bv finish verifies all on HEAD and prints the verbatim Receipt.

Artifacts: receipts.md (per stage) + Section 13 Final Receipt
All 8 Registered Lifecycle Hooks (hooks/hooks.json → bin/bv hook → scripts/guard.py & scripts/events.py)

1. PreToolUse pre-tool

Main barrier across Write, Edit, MultiEdit, NotebookEdit, Read, Grep, Glob, Bash, PowerShell, WebSearch, WebFetch, AskUserQuestion, Agent, Task and mcp__*. Runs inside a 10s budget: crashes, timeouts or broken state.json fail-closed for writes. Logs deny and AskUserQuestion waits. A bv escape hatch gets permissionDecision: "ask": the user approves the call; in full mode --use-real-env and --extra-round are denied, --reason and --fewer-tests pass into the report.

Exit 2 blocks tool · ask = user approves · Active while run is open & guard=on

2. PostToolUse post-tool

Appends completed tool calls to live/<run>/agents/<id>.jsonl, saves secret-masked input/output to out/<call>.txt (up to 1M chars), links spawned subagent tokens/duration, and captures SubagentHandback final answers.

scripts/events.py · Masked before touching disk

3. PostToolUseFailure tool-failed

Records failed tool calls (ok: false) and full masked error output. Panels distinguish normal TDD red-then-green test runs (gray ✗N) from unresolved hard failures (red ✗N).

Powers error filter (hotkey e) & Last error jump

4. SubagentStart agent-start

Records the exact start timestamp and agent type (bv-executor, bv-reviewer, etc.) so panels map active subagents to their stage or ticket in real time and flag 5-minute silence.

Links agent_id → stage / ticket tree

5. SubagentStop agent-stop

Records subagent completion and writes its full masked final answer to out/stop-<agent>-<time>.txt. bv reads bv-coverage, bv-reviewer and bv-blind proofs straight from here—never from the orchestrator.

Tamper-evident checker proof for G2, spot/branch review & G4

6. Stop stop

Fires when the main orchestrator turn ends. If no non-monitor background tasks are running, writes a wait event so the VS Code panel and web dashboard display "⏸ Waiting for you".

Ignores persistent dashboard monitor process

7. SessionStart session-start

Fires on startup|resume|compact|clear. Injects live bv status and resume instructions into additionalContext so a compacted or reopened session continues seamlessly without re-running the slash command.

Automatic context recovery across compactions

8. UserPromptSubmit prompt

Scans human-typed messages for API keys, tokens and private keys before they leave for the model: blocks the prompt with a revoke warning on a hit, or writes a resume event to clear "Waiting for you".

Prevents accidental secret exposure in chat
Hard Guard Rails, Mechanical Audit & Live Observability

Role, Zone & Self-Protection guard.py

Orchestrator cannot write project code (Write/Edit or shell redirects/cmdlets/interpreters). bv-executor writes only inside its ticket's Zone. Nobody writes state.json, live/, the plugin folder or .claude/settings*.json. Non-bv-* agents and mutating MCP tools are blocked. Escape hatches need the user, not the model: Claude Code asks them to allow guard=off, init --force, --use-real-env, --extra-round (semi/interview also set … --reason, --fewer-tests); a subagent never runs them.

Emergency switch: bv set guard=off (the user approves the call; sets permanent guardWasOff report flag)

Secret, Git & Checker Isolation guard.py

Blocks reading/searching .env, writing secrets to files/web queries, git push, publish, reset, clean -f, stash, history rewrites, whole-tree git add, subagent git commit and encoded PowerShell. Isolates bv-blind to its history-free clone and bv-research/bv-scout to single files.

Unnests bash -c, pwsh -Command, eval & interpreter heredocs

Mechanical Audit Engine scripts/audit.py

Scans whole tree for secrets & key files (blocker), changed files for dangerous calls (eval, exec, shell=True, SQL concat, XSS, tls-off, weak crypto) and junk code (orphans, unused exports/deps, debug leftovers, stubs, commented code), plus npm audit / pip-audit / cargo audit.

Runs per-ticket on bv commit and branch-wide in Phase 6 (audit.md)

VS Code Run Panel & Prompt Strip hooks/register.tsx

Opens beside the chat on /software-architector:build. Shows mode/tier/tokens, 5-min silence alerts, "⏸ Waiting for you", gates G1–G5, stage → ticket → agent tree, changed files and full tool I/O. Above-prompt strip provides Panel (b) and Web (w) buttons.

Commands: /bv-panel · /bv-web · Hotkeys: a, e, f, p, n

Local Web Dashboard & Monitor dashboard.html

Started automatically via monitors/monitors.json (bv serve on 127.0.0.1:87NN/?k=<key>) or bv web. Protected against DNS rebinding (Host check + per-start random key / HttpOnly cookie), refreshes every 2s, and shuts down automatically on bv finish.

One server per project · Same interactive agent/call inspector

Isolated Check Runner & Process Jobs scripts/bv.py

bv commit and bv verify execute setupCmd / checkCmd / e2eCmd in Git Bash with a scrubbed allowlist environment (CI=1, no session API keys) inside a Windows Job Object / POSIX process group so timed-out checks and orphan dev servers are killed cleanly.

Default checkTimeout: 540s · Masked logs in live/<run>/checks/
